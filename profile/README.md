<details>
<summary><b>A few of our norms</b></summary>
<br>

- **Write clear PRs.** A good description saves the reviewer time and becomes documentation later.
- **Small, reviewable changes** beat large ones - easier to review, easier to revert.
- **Document the why, not just the what.** Code shows what happens; commits and PRs should explain why.
- **Ask early.** If a ticket or requirement is unclear, raise it before writing code, not after.

</details>
